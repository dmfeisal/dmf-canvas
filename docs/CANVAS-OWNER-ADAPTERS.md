# Canvas owner adapters

Status: Internal extraction contract, 20 October 2026. This records the current adapters before extending the lifecycle specimen. Existing portfolio owners remain authoritative; no production owner migration is included.

## Current registration inventory

`rg '\.register\(' public/js` identifies two production registration sites:

| Registration | Variants | Methods and capabilities |
| --- | --- | --- |
| `canvas-text.js`, `initializeText` | Authored editable text, local Text and Sticky Note, image logos/portraits and static composites | `capture`, `restore`, `reset`, `info`, `beginMove`, `beginTransform`, `dispose`; conditional `copyData`, `duplicate`, `textStyle`, `paperColor` |
| `note-transforms.js`, lazy `select` | Private palette notes/local Text/copies, published Guestbook notes, case-detail paper and case-flow paper | `capture`, `restore`, `reset`, `info`, `beginMove`, `beginTransform`, `dispose`; gallery-only `copyData`/`duplicate`, conditional `paperColor`, `noteText`, `textStyle` |

Pencil/Highlighter create local SVG inside text/private-paper factories; their geometry owners come from these same sites, not a third adapter. Home Services uses composite objects through `canvas-text.js`. Guestbook/case/gallery scripts provide positions through `dmf:note-position`; they do not register a separate shared-tools owner. The 404 recovery link has page-local movement and is not a shared-tools registered owner.

### Methods

- `capture()` returns the authoritative owner state. Text includes x/y, scale/angle, width/custom wrapping, alignment, editor HTML/content-change state, inline typography and optional paper color. Paper includes scale/angle, shape x/y, host position and optional paper/text-size/full typography snapshots.
- `restore(state)` applies owner state, containment and change notification. Current implementations also select their element. That global selection side effect must be removed or injected before production adoption.
- `reset()` restores owner defaults. Host reset/storage effects stay separate; resetting core metadata must not authorize storage deletion.
- `info()` returns `{ angle, width, height }`; geometry is scaled CSS pixels, with page-owned camera conversion elsewhere.
- `beginMove()` returns null for unsupported movement (including case-flow paper), otherwise `{ limits, move(dx,dy) }`. Limits and deltas are screen-space offsets relative to gesture start, not absolute positions. Text uses bounded translation; paper maps through camera/rotation/scale, while Guestbook uses layout coordinates.
- `beginTransform()` returns null for unsupported transforms or `{ cx,cy,width,height,angle,min,max,bounds,apply(factor,turn,dx,dy) }`. It caches start geometry and coordinate mapping. This seam is not migrated by the specimen.
- `copyData()` captures a template/content/geometry snapshot. `duplicate(dx,dy,data?)` delegates object creation to the owner/host factory. Core cannot infer copy eligibility from text content or DOM attributes.
- `dispose()` currently releases text resize/reset/change references or paper WeakMap state. Most existing per-element/delegated listeners remain load-lifetime. These are not complete instance teardown implementations.
- `textStyle` exposes `read()` and `prepare() → { apply(key,value), finish() }`; private-board styles also have `capture`, `restore`, `reset`. `paperColor` and `noteText` expose `read`, `capture`, `restore`, `reset`, `changed`, `set`. These optional capabilities are not migrated here.

Shared `canvas-tools.js` wraps these owner snapshots with lock, position-lock, sibling layer, group, layer-name and local-copy presence metadata. Its global `register` currently returns no disposal handle. Its selection, history and presence registries must be separated before adopting existing owners.

## First isolated registration contract

The provisional types live in `public/js/canvas-instance.d.ts`. `register(element, owner)` accepts a contained, non-overlapping element and a semantic name, `capture`, `restore`, `dispose`, and optional `beginMove`/`beginTransform`/`beginEdit`. Snapshots must be structured-cloneable, JSON-shaped data. Capture must not mutate the owner; restore must not trigger global selection, saving or publishing. Core clones snapshots before retaining or restoring them. It owns a maximum of 50 retained registrations (present plus undone creations) and 50 history actions per instance. Disposal handles are idempotent and discard only that owner's history references.

The isolated Text adapter accepts a direct, positioned, initially untransformed static text child of an unrotated, unzoomed host. It owns one readonly editor wrapper with five removable listeners and seven accessible button handles and restores its initial translate/scale/rotate/width/transform-origin and owned control variables on disposal. Content, typography and DOM order remain authored. `public/css/canvas-instance.css` styles only dedicated isolated handle/editor/paper classes; production styles/selectors remain separate. Rejected registrations remain the caller's responsibility to dispose if their adapter factory already allocated controls.

Mouse/pen translation has a 4px threshold; touch remains native page scrolling. Corner handles proportionally scale 0.5–1.8× around the opposite corner, including rotated text. Side controls sit 16 screen pixels outside the edge to avoid overlapping corner hit areas on short text. Cached dimensions add corner separation when scaled text is smaller than the 24px targets; proportional/rotation updates still avoid layout measurements. Side handles change local width with reflow (80px minimum or available width) around the opposite side midpoint. Rotation uses the gesture-start center with Shift 15° snapping. Geometry is cached at gesture start; proportional/rotation pointer updates do not measure layout. Side reflow needs owner-local post-layout anchor measurements. Release and restore may scale/move the text to fit its host (8px inset, 32px reserved below); these bounds take precedence over an anchor or old position.

With a handle focused, arrows change corners by .05 scale, side widths by 10px (Shift 40px), or rotation by 5° (Shift steps snapped to 15°). On the object/root, arrows retain 1/10px movement. Held keys and each pointer gesture create one history action. Escape, lost capture, pointer cancellation and host interruption roll back active transforms without clearing Redo. Undo/Redo remain instance-local and leave native fields alone. Stop/remount removes controls/styles and starts fresh history without disturbing siblings.

The provisional `beginTransform(kind, point|null)` session returns `pointer(dx,dy,shift)`, `step(direction,shift)` and optional `finish()`. It covers single-handle routing; it is deliberately distinct from the production no-argument group-transform `beginTransform()` shape inventoried above. Existing owners still need an explicit wrapper/migration and parity review. This contract reuses production anchor/projection math and handle sizes without installing its global listeners.

`beginEdit()` exposes the contained editor plus `finish()` and optional `focus()`. Core captures before/after snapshots and keeps one editing session per instance, with native text Undo and one canvas history action on finish. Owner snapshots now include plain `content` or null for the original authored nodes, along with x/y/scale/angle/width. Typing/line breaks/plain paste preserve the local top-left anchor; finish-time bounds may fit the result. Done, Escape, Ctrl/Command Enter or outside focus finish; canvas `cancel` also finishes typing. Normal typing remains native, and safe paste fallback cannot guarantee native paste Undo. Text is capped at max(240, original source length), with beforeinput, IME, selection and paste guards. Disposal releases all editor listeners, removes the wrapper and restores the actual authored nodes, styles and controls without saving.

The Sticky Note adapter in `canvas-instance-sticky.js` composes `createTextOwner` with `{ name: 'Sticky Note', widthHandles: false }`. Only the adapter creates/removes/reattaches paper; core routes `register(..., { created: true })` presence history through `setPresent(boolean)`. Notes have a fitted square up to 240px, five handles, fixed scrollable text area, system typography and the shared editing/transform contract. `capture/restore` add a validated `paperColor` key; optional `paperColor.read/set` accepts yellow/blue/pink, with shared token/local fallback artwork and dark ink. Core `execute('paper-color', value)` records one snapshot action only when it changes. Text has no paper-color capability. Core state exposes selection name, current paper color and retained creation capacity for host controls.

Creation is one action, separate from later typing/transforms/colors. Undo creation removes the note from DOM/focus but retains its owner for Redo. Capacity includes absent retained notes, preventing an Undo/create loop from allocating indefinitely. History branching disposes absent owners whose last reference is discarded; active owners remain capped at 50 even when creation history expires. Stop/destroy releases every created owner, present or absent, with idempotent listener/DOM cleanup. The examples dispose a factory allocation if registration fails. This is bounded local presence, not production copy/delete/group migration or saving.

Host resize finishes/cancels active input, then calls `execute('contain')`. This restores each present owner through its own snapshot/bounds logic without selecting, saving or adding history; absent creations fit when redone. It keeps desktop-created paper inside a narrowed or RTL host before editing starts. This is an explicit host hook, with no instance observer/window listener.

`canvas-instance-pencil.js` adds a non-editable Drawing owner through the existing geometry factory (`editable: false`, five handles). It has no editor wrapper/listeners, text or paper capability. Its local SVG is immutable artwork, with bounded validated points and 2/4/8px Primary/Blue/Red ink; capture/restore remain geometry-only. The Pencil controller uses one `beginCreation(cancel)` reservation per stroke, committing through created registration and the same presence/history pruning as paper. Cancelling preserves Redo and drops its preview/RAF. Its seven root capture listeners and core subscription are explicitly disposed, including on instance destruction. Core state exposes `creating` and blocks competing selection/registration/commands. Mouse/pen drawing, native touch scrolling, keyboard guards, bounds and sample limits are detailed in the Canvas guide. No production owner or PNG renderer is migrated.

Mixed-object selection now composes the same owner `beginMove()` sessions. Core caches a whole selected plan and intersects screen-delta limits, applies one rigid delta to all members, and stores before/after owner snapshots as one batch history action. Failed/unsupported plans do not partially move; cancellation restores each member. Batch Undo/Redo restores/reselects all members; disposing a member discards the whole batch action and safely cancels affected active gestures. Individual shape handles and paper color stay single-object-only. `selectMany` validates unique same-instance owners, while frozen state IDs/count and `setMultiple` drive host controls. The preflight snapshot aggregate is limited to 64 KiB and each batch history action to 128 KiB, retaining existing 50-object/50-action limits. Group-resize and system clipboard support remain outside this step; the later document contract adds optional serialization. Detailed focus/modifier/history boundaries remain in the Canvas guide.

The plain HTML example in `public/examples/canvas/` mounts two authored Text owners directly and creates notes through explicit registration without portfolio scripts/styles/fonts or backend calls. Host controls, themes and lifecycle hooks remain outside core. The example is a technical noindex reference, not a published package. Its host calls interruption/finish before teardown or resize, and remounts only previously running canvases on BFCache restoration with fresh state.

This tests owner geometry/editing/history isolation, not full group transforms, position locks, object clipboard, style, camera or export parity. The production migration gate remains open; browser policy, complete listener/CSS ledgers and package decisions still need review.

Focused viewport/storage checks exclude only the host-owned Spotify widget position key, which its existing resize handler persists. All other local data keys and blocked server-write assertions remain strict.

The isolated prototype now implements Delete for whole created selections, Duplicate for mixed serializable owners, and local board-file Save/Open through an optional document adapter. Owners expose `serialize()`; core receives injected validation/factories and returns detached versioned data without choosing storage. Structural operations are atomic presence/history batches; Open validates then starts fresh history. See [the document format guide](CANVAS-DOCUMENT-FORMAT.md) for limits and scope. No public package, production-owner migration or shared/public storage is added.

The isolated prototype supports mouse/pen marquee selection from empty host space: a 4px threshold, live axis-aligned intersection with cached owner bounds, Shift-at-start union, and a theme-blue pointer-inert overlay. Empty click clears; Shift-click on empty space preserves selection. Escape, Tab, pointer cancellation/lost capture, outside focus, host interruption, owner disposal and teardown discard the overlay and restore the prior usable selection. The active marquee blocks structural/history/file commands through existing busy guards; selection adds no history or document data. Native editors/controls and touch scrolling retain their input. Geometry is measured once at pointer-down for at most 50 owners, with no move-loop scans/layout reads, observers or new listeners. Different instances remain independent; grouping and group transforms are unchanged.

The isolated prototype supports owner-independent Lock/Unlock metadata through `execute('lock')` (toggle), explicit `execute('lock', true)` / `execute('lock', false)`, `canLock` and tri-state `selectionLocked`. A mixed selection locks all; a wholly locked selection unlocks all. Each changed batch is one history step; no-op locking adds none. Locked owners remain selectable by click, keyboard, Select all and marquee, but cannot move, transform, edit, change color, duplicate or delete. Mixed movement/duplicate/delete plans reject as a whole. Individual editing still isolates an unlocked member. Handles hide and status announces locks; native fields and other instances remain independent. Host containment may still fit locked geometry on resize. Stop/disposal restores pre-existing lock attributes, and file Open restores validated optional boolean `locked` metadata (missing means false for older version-1 files). No lock data is written to backend/localStorage or production owners.

The standalone prototype supports Bring forward, Send backward, Bring to front and Send to back through instance commands and native host buttons. Reorder unlocked direct-host siblings as one stable selection batch; preserve DOM/Tab order, owner geometry and other instances. Locked or nested selections reject as a whole; boundary no-ops add no history. Instance metadata history restores exact prior inline z-index values/priorities on Undo and authored values on disposal. Hidden retained owners do not consume visible layer steps. Save emits optional integer `layer` ranks (0–49) on every record; Open requires a complete unique contiguous order when present, validates before mutation, and restores cross-type original/created stacking. Older version-1 files without ranks open in originals-then-created record order. Chrome remains above objects. No backend/storage or production canvas behavior changes. See `docs/CANVAS-DOCUMENT-FORMAT.md` for the file contract.

Standalone Arrange uses native disclosure/button controls on both demos: `align-left`, `align-center`, `align-right`, `align-top`, `align-middle`, `align-bottom` (2+ owners) and `distribute-horizontal` / `distribute-vertical` (3+ owners). All selected owners must be unlocked, present and movable. Align transformed visible bounds to their combined outer edges/center; distribute in stable visible-leading-edge order with equal non-negative gaps while preserving outer bounds and the other axis. Prepare owner movement sessions, snapshots and visible rectangles before writes, reject complete plans outside any owner limits or with negative distribution gaps, and roll back the whole selection on owner failure. Each changed arrangement is one bounded batch Undo/Redo; no-ops preserve history/Redo. State eligibility is geometry-free; overlap/bounds rejection is announced on activation. Keep selection, rotation/scale/content, DOM/Tab order, instance isolation, native editors/touch and existing file geometry unchanged. No new listeners, pointer-loop layout work, dependencies, storage or production canvas changes.

Standalone Group/Ungroup uses flat, instance-owned membership metadata, native buttons and contextual Ctrl/Command G / Ctrl/Command Shift G. Group requires 2+ ungrouped unlocked movable owners with a valid shared movement plan; ungroup dissolves selected whole groups in one metadata Undo step. No nested groups or implicit merging. Click/focus, selection APIs, Shift toggles and marquee expand to whole present groups; movement, locks, layers, duplicate and created-only deletion retain complete selections. Arrange stays disabled until ungrouping. Enter/F2 or double-click temporarily isolates one editable member; finishing and edit Undo/Redo restore group selection without changing membership. Native editors keep their keys. Duplicate remaps membership to independent new groups, presence Undo restores it, and owner disposal dissolves surviving singleton membership. Save emits optional integer `group` IDs (1–50); Open validates 2+ members per referenced group before mutation, remaps to fresh instance IDs, and treats missing group fields as ungrouped legacy data. Preserve DOM/Tab order, owner snapshots/geometry/content, 50-object/50-action bounds, other instances, native touch and all production/public/storage boundaries. No wrappers, global listeners, polling or pointer-loop layout reads are added.

Standalone Copy/Paste is a same-page object clipboard, explicitly shared by the host: import `createObjectClipboard` from `canvas-instance-clipboard.js`, then pass the same `clipboard` option to participating `createCanvas` calls. It never reads/writes the OS clipboard or storage; Ctrl/Command C/V and native Copy/Paste buttons route only idle canvas input, while native editors/fields keep system text clipboard behavior. Copy requires a complete unlocked serializable selection, preserves source state/history, snapshots validated records in visual layer order with local visible bounds, and retains at most one 128 KiB / 50-object transfer. Paste reconstructs new created owners, remaps groups, preserves supported typography/paper/drawing styles and relative transforms/positions, and applies one shared preferred 24px offset clamped to target bounds. Reject the whole paste if it cannot fit intact, geometry changes during reconstruction (including incompatible host font/layout), validation fails, or the 50-retained-owner cap would be exceeded; dispose provisional owners without changing target selection/history. Each successful paste is one presence Undo/Redo action. Clipboard updates refresh only explicitly connected instances; source destruction retains the data while another instance is connected, and last-instance teardown clears data/subscriptions. No global clipboard singleton, DOM references in transfers, permission prompts, async jobs, new global/root listeners or production canvas/public-data changes. Cross-page/system object clipboard support remains outside this step.


### Standalone embed settings

The isolated prototype now accepts per-instance `readOnly` and partial `tools` options, runtime `configure(patch)`, frozen state settings, command/shortcut enforcement, and host-owned settings controls in both demos. Defaults preserve behavior; changes finish typing, cancel gestures/creation, and retain history. Settings are excluded from board files/storage and production owners. See [the Canvas guide](CANVAS.md#standalone-embed-settings) for tool keys, lifecycle and read-only boundaries.


### Standalone change events

The isolated core now exposes `subscribeChanges`, revision/source metadata, saved-checkpoint dirty state and stale-safe `markSaved(revision)`. Completed user edits and history/file operations notify independently per instance after the current stack; no-op, selection, focus, settings, initialization and host lifecycle/layout work stay outside the stream. Both demos show unsaved status. See [the Canvas guide](CANVAS.md#standalone-document-change-events) for delivery, checkpoints, lifecycle and scope. Persistence remains host-owned; the optional local-draft adapter is described below, without production-owner migration.


### Optional local-draft host adapter

`canvas-instance-drafts.js` now demonstrates opt-in, keyed local recovery outside core, with debounced completed-edit saving, explicit Restore/Discard, separate draft/file status, Retry on failures, bounded records, best-effort changed-record detection and lifecycle cleanup. `canvas-instance-draft-controls.js` owns the two demos' native controls; opt-in itself is not persisted, and normal production canvases/storage remain unchanged. See [the Canvas guide](CANVAS.md#optional-standalone-local-drafts) for schema, lifecycle and storage boundaries.


### Standalone toolbar renderer

The standalone spike now has a reusable DOM-only toolbar factory and scoped stylesheet, with bundled licensed Lucide SVG, action/state updates, real-control adoption in both demos, Select, 36px targets, a single native tooltip, roving keyboard/RTL navigation and complete teardown. It delegates commands and file/draft policy to hosts and leaves production owners unchanged. See [the Canvas guide](CANVAS.md#standalone-embed-toolbar) and the plain HTML example README for the API and ownership contract.

The isolated embed's `canvas-instance-theme.js` adapter owns wrapper-scoped Light/Dark/System/host-inherited appearance and optional surface/grid/selection/toolbar/ink/line colors. It has no owner or command dependency: active edits, transforms, selection, history and serialized object colors remain intact. Dispose it at final host teardown, separately from Stop/Start. See `CANVAS.md#standalone-embed-appearance`.

Standalone image objects now use `canvas-instance-image.js` (non-editing owner), `canvas-instance-image-data.js` (bounded raster validation) and optional `canvas-instance-image-controls.js` (local upload/drop). Imports preserve transparency as PNG, use JPEG for opaque images and progressively resize from ≤512px to fit 32 KiB encoded; sources are capped at 10 MiB/16 megapixels/8192px. Images share selection, proportional transforms, layers, locks, duplication/deletion, Undo and local board-file/draft/clipboard support. Keep `tools.image`, cancellation/URL cleanup, native fields and existing board/clipboard limits; see the Canvas guide’s standalone image-object contract. No production/shared storage or upload behavior changes.

Image quality/accessibility update (23 October 2026): `canvas-instance-image-encode.js` performs bounded, cancellable progressive encoding without flattening alpha. The example hosts announce import stages, source/stored dimensions and format/size, expose Cancel import and provide a native image-description field. Description changes are owner-backed single Undo actions, update both accessible labels, survive files/drafts/copies, and respect locks/read-only/tool permissions. Source metadata is discarded; board/clipboard budgets and local-only data boundaries remain unchanged. See the Canvas guide and [grouped roadmap](CANVAS-ROADMAP.md).


Extraction rehearsal (23 October 2026): the isolated prototype runs in a separate, dependency-free local host and the copied plain HTML reference. Hosts own resize observation (cancel active gestures, then contain objects), pending frame/observer disposal, file URLs and draft policy. This verifies prototype independence, not production parity or a stable public API. See [reproduction, validation and remaining boundaries](CANVAS-EXTRACTION-REHEARSAL.md).
