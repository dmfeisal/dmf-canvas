# Private 0.2.0 API contract

The package export map and installed TypeScript declarations define supported names and payloads. Deep imports under `js/`, example helper properties and portfolio globals are implementation details, not supported consumer APIs. This is an initial development contract; it is not a stable 1.0 promise.

## Entry points

| Import | Responsibility |
| --- | --- |
| `dmf-canvas` | `createCanvas`, `resolveSettings`, `canvasToolNames`, instance and owner types |
| `dmf-canvas/owners` | Text, Sticky Note, Drawing, Image and Shape owners; document adapter |
| `dmf-canvas/pencil` | Optional scoped Pencil input controller |
| `dmf-canvas/clipboard` | Explicitly shared page-local object clipboard |
| `dmf-canvas/toolbar` | Optional action toolbar |
| `dmf-canvas/theme` | Scoped System/Light/Dark/Inherit theme adapter |
| `dmf-canvas/drafts` | Optional host-injected local draft storage |
| `dmf-canvas/images` | Raster validation, dimensions and encoding helpers |
| `dmf-canvas/canvas.css` | Object, selection, handles and cursor styles |
| `dmf-canvas/toolbar.css` | Optional toolbar styles |

## Instance lifecycle

Call `createCanvas(host, options)` with a connected, positioned and sized HTML surface. One live instance owns one surface. Inject document and clipboard adapters explicitly; core does not mount a toolbar, access storage or upload content. Importing entry points does not require a DOM; calling DOM factories does.

Register each element with an explicit owner. `register` returns a disposer; owners implement bounded capture/restore/dispose and optional movement, transform, editing, serialization, presence, paper color or image description capabilities. Capabilities determine command availability. Created-object presence and retained history are instance-scoped. See the installed `CanvasOwner` declaration and owner-adapter guide for exact signatures.

`getState()` returns a read-only snapshot. `subscribe()` has no initial callback: render once yourself. `subscribeChanges()` delivers ordered completed-change notifications after the current stack, with no initial event. Retain and call unsubscribe functions. `markSaved(revision)` acknowledges only the revision persisted by the host.

`configure(patch)` changes read-only/tool policy and snapping while preserving omitted values. `snapping: {align, grid}` (0.4.0-alpha.1; default `{align: true, grid: false}`, also accepted by `createCanvas`) snaps pointer drags of a selection: `align` within 6px of other objects' left, centre and right (and top, middle and bottom) edges, up to 80 peers, and `grid`, when nothing aligns, to the 24px background dots. Alt/Option held during a drag bypasses it. Keyboard nudges, resize and rotate never snap, and a snap that would leave the containment area is skipped. `getState().settings.snapping` reports it; it never enters saved data. While a snapping drag runs, core shows a vertical and a horizontal guide on the line each axis snapped to, and pink gap guides labelling the nearest non-overlapping distance (screen pixels, to a tenth, up to 1000px) to a peer that shares the other axis. Guides are reused, pointer-inert, `aria-hidden` overlays inside the host (`.canvas-instance-guide`, `.canvas-instance-gap`), hidden on drop, Alt and cancellation, and removed by `destroy()`. Policy guards interactions and commands, not merely visible controls. `select`, `selectMany`, `setMultiple` and `focus` return booleans; provisional `beginCreation` may return null. `execute` and other declared command-result methods return `{ok, reason}`; consumers must inspect the result rather than assume success. Invalid schemas and mounting/registration misuse may throw; do not treat every method as a result-only API.

Commands cover movement, editing, selection, locks, grouping, arrangement, layer order, copy/paste, duplicate/delete, history, paper colors, image descriptions, containment and cancellation. Use the installed `CanvasInstance` overloads for command names and payloads. Camera and export commands remain outside this baseline.

`saveDocument()` returns a bounded board document; `loadDocument(unknown)` validates before applying it. Styled records and font sizes over 200px require board/clipboard schema 2. Otherwise saves/transfers remain schema 1; both are readable, and schema 1 rejects typography. Draft envelopes remain version 1. Clipboard sharing is opt-in within a page, not OS clipboard or cross-origin messaging. See `TEXT-FORMATTING.md` for migration details.

Dispose optional draft/Pencil subscriptions before destroying the canvas, then dispose visual adapters. `destroy()` is idempotent and releases instance state; hosts still own their listeners, observers, pending frames, file reads, object URLs and framework lifecycle. Host resize handlers cancel active gestures then contain objects. Native fields and editing retain their own keyboard behavior. Use the tested framework recipes for lifecycle examples.

## Compatibility changes

All modules, CSS and declarations share one package version. Before 1.0, compatible fixes increment patch; features or incompatible contracts increment minor. Breaking changes require migration notes. After 1.0 use Semantic Versioning. Released archives and tags are immutable; file schema changes need explicit validation/migration policy independently of package bumps.

## Selection inspector (0.2.0)

`getInspector()` returns visible selection bounds (`x`, `y`, `width`, `height`), `rotation`, `relativeRotation` and `editable`, or null for no selection, unsupported owners, active editing/creation/gestures or destruction. Locked/read-only selections remain measurable but not editable. Values use CSS screen pixels relative to the surface inside its border. Current owners support untransformed host surfaces; no new camera or CSS-transformed-ancestor support is claimed.

`execute('inspect', {field, value})` accepts one of `x`, `y`, `width`, `height` or `rotation`, and a finite numeric value. Width/height scale proportionally around the visible top-left, not text reflow or image stretching. Single rotation is absolute; multiple-object rotation is a relative turn around the combined center and its UI resets to zero. Plans intersect owner scale/bounds limits; translation and size clamp to applicable limits. Rotation that cannot fit is rejected. Successful batches create one history step, failures restore every captured owner, and subpixel no-ops create no history. Read actual values after applying. Existing serialization captures the geometry without a file-schema change.

Custom owners opt in through `geometry.read()` and `geometry.prepare(target)`. Read returns a finite `CanvasGeometry` with center, unscaled border-box dimensions, scale, angle, permitted scale range and bounds in the same surface coordinate space. Prepare must not mutate; it returns one apply closure or null. The closure applies geometry only, preserving content, metadata and style capabilities. Core captures/restores owner snapshots and owns the batch/history. One unsupported or locked member prevents the whole batch. There is no DOM fallback for unknown owners.

`createCanvasInspector(container, {canvas, trigger})` from `dmf-canvas/toolbar` mounts one optional native popover for a contained HTML button. Call its `toggle()` from the trigger's existing dispatcher, load `toolbar.css`, and dispose it before the canvas/toolbar. It restores trigger attributes and disabled state. The caller owns trigger dispatch; the inspector owns fields, subscriptions and dismissal listeners. No storage, persistence service or publication is added. See the configurator for the complete host recipe.

## Pencil and Highlighter (0.3.0-alpha.1)

`createPencil(canvas, host, onChange)` is one input controller for every drawing tool (Pencil, Highlighter, stroke Eraser and Shapes), so at most one is armed. `setTool('pencil'|'highlighter')` switches tools without arming; `setActive(true)` arms the current tool. Each tool keeps its own settings: Pencil widths 2/4/8 with `primary`/`blue`/`red` ink; Highlighter widths 12/20/32 (default 20) with `yellow`/`pink`/`blue` ink (default yellow), drawn at 32% opacity to match feisal.id. `setWidth`/`setColor` validate against the current tool. `getState()` reports `active`, `tool`, `width`, `color` and `drawing`. Keys on the focused canvas: P toggles Pencil, Shift+P toggles Highlighter, E toggles the stroke Eraser, V or Escape return to Select. The existing `pencil` tool permission governs Pencil, Highlighter and Eraser (the Eraser also needs `delete`); there is no separate `highlighter` setting.

`setTool('shape')` arms the Shapes tool (0.3.0-alpha.3), governed by the `shapes` tool permission. `setShape(kind)`, `setFill('none'|'tint')` and `setCorners('sharp'|'round')` set what the next shape uses, with the Pencil inks and widths through `setColor`/`setWidth`; `getState()` also reports `shape`, `fill` and `corners` (null for other tools). Dragging on empty space draws a shape (Shift keeps a square or circle, or snaps lines and arrows to 45°), a click places a 120 × 80px default, and Enter places one at the centre of the visible surface. Keys R, O, D, L and A arm rectangle, ellipse, diamond, line and arrow. Each shape is created through `beginCreation(cancel, 'shapes')`, selected and focused, and the controller returns to Select. Touch input is ignored, as for Pencil.

`setTool('eraser')` arms the stroke Eraser: dragging marks touched Pencil/Highlighter strokes (faded through `data-canvas-instance-erasing`) and release calls `execute('erase', elements)`; pointer cancellation and Escape restore them. `execute('erase', elements)` takes 1–50 elements, removes the created, unlocked, ungrouped Drawings among them as one history action (change source `erase`), keeps the rest, and fails with `unsupported` only when none qualify. For an Eraser, `getState()` reports `width` and `color` as null and `drawing` during the gesture.

`drawingPalettes` from `dmf-canvas/pencil` lists each tool's semantic inks with display colours and its thin/medium/bold widths, for host swatches. Boards still store only the semantic keys.

A highlight is a Drawing owner (`createDrawing(host, points, {tool:'highlighter', width, color})`) named "Highlight", with the same geometry, locks, layers, grouping, Duplicate, Copy/Paste and history. Its record is `type:'drawing'` plus `tool:'highlighter'` and semantic `ink`/`strokeWidth`; resolved colours are never stored. See [compatibility](COMPATIBILITY.md#highlighter-schema-3) for versioning.

## Shapes (0.3.0-alpha.3)

`createShape(host, style, layout)` from `dmf-canvas/owners` creates a geometry-only shape owner: `rectangle`, `ellipse`, `diamond`, `line` or `arrow` (`shapeKinds`). `style` takes the Pencil `ink` (`primary`, `blue`, `red`) and `strokeWidth` (2, 4, 8), `fill` `none` (default) or `tint` for closed shapes, `corners` `sharp` (default) or `round` for rectangles, and two box-local `points` for lines and arrows. `layout` places the box in host pixels. Register the result like any owner. Shapes have eight resize handles plus rotate: sides change one dimension, corners change both (Shift keeps the ratio), the opposite edge or corner stays fixed even when rotated, and the artwork is redrawn so strokes keep their width while line points stretch with the box. Keyboard steps are 10px (Shift 40px). Side handles hide while the box is under 48px in that direction. Shapes share geometry, locks, layers, grouping, Duplicate, Copy/Paste and history, and the stroke Eraser never removes them. Records are `type:'shape'` with only these semantic keys; SVG, CSS and resolved colours are never stored. See [compatibility](COMPATIBILITY.md#shapes-schema-4).

`TransformHandle` adds `n` and `s` for these free-resize owners, and `createTextOwner` takes `freeResize` and `onBox(width, height)` to build them. The Selection inspector's Width and Height still scale proportionally. Hosts draw shapes with the Shapes tool in `createPencil` (above). `execute('shape-style', patch)` restyles every selected shape as one history step (change source `shape-style`); `patch` takes any of `ink`, `strokeWidth`, `fill` and `corners`. Each shape applies only the keys its kind supports (fill skips lines and arrows, corners apply to rectangles). The command needs the `shapes` tool, fails with `unsupported` if the selection contains anything that is not an unlocked shape or if nothing applies, and with `invalid-style` for unknown keys or values. `getState().shapeStyle` reports the selection's shared `ink`, `strokeWidth`, `fill` and `corners` (null when mixed or not applicable) with `canFill` and `canRound`, or null unless the selection is only unlocked shapes. Custom owners opt in with `shapeStyle.read()` and `shapeStyle.prepare(patch)`, which returns `{apply}` or null. Excalidraw mapping follows the [Shapes proposal](prd/SHAPES.md).

## Toolbar and More menu (0.3.0-alpha.1)

`createCanvasToolbar(container, {actions, label, orientation, moreLabel})` renders a roving-focus toolbar of icon buttons with one shared tooltip. `orientation:'vertical'` (default `horizontal`) renders a tool rail with Up/Down navigation and side tooltips. An action with `menu:true` moves into one generated More menu (`moreLabel`, default `More actions`): a manual native popover with `role="menu"`, sections named by each action's `group`, icon/label/shortcut rows, contextual hiding via `update(id,{hidden})`, checked rows via `pressed`, keyboard navigation, outside-press/scroll dismissal and focus return to More. The id `more` is reserved. Generated buttons and menu rows carry `data-toolbar-action="<id>"` as a stable host and test hook. `toolbar.css` also provides optional `.canvas-embed-chrome` slots (`tools`, `history`, `selection`, `help`) for the floating layout. Groups, icons, labels and placement follow the [toolbar standard](design/TOOLBAR.md); hosts still own commands, state and layout.

## Text formatting (0.2.0)

`getTextStyle()` returns common `font`, `size`, `weight`, `align`, `wrap`, supported `weights` and `editable`; mixed values are null. It returns null during editing/creation/gestures or when any selected owner lacks the explicit textStyle capability. Original font choices compare actual families for mixed selections; alignment is physical Left/Center/Right, including RTL. Read-only, disabled Text and any lock prevent formatting.

`execute('text-style', {field, value})` supports Font (`original`, `sans`, `serif`, `mono`), Size (8-320 CSS px), Weight (400/500/600/700), Alignment (`original`, `left`, `center`, `right`) and Wrapping (`auto`, `fixed`). `{field:'reset'}` restores each owner's initial text styles and wrapping. Invalid inputs return `invalid-style`; values are never coerced from CSS or URL strings. The inspector exposes these controls only for complete eligible Text selections.

Custom owners opt in with `textStyle.read()` and mutation-free `textStyle.prepare(field, value)`, returning `{apply, finish}` or null. Core captures every owner before preparation, applies all writes, then finishes anchor compensation/containment and records one bounded history action. Application failures restore the entire batch. Current Text owners preserve local top-left anchors through reflow/rotation/scale; canvas bounds take precedence. Reset retains text content and current transform except necessary containment. Copies use their cloned appearance as their reset baseline. No font service, network font loading, new storage service or arbitrary CSS capability is introduced.

## Experimental portable documents (local development)

`savePortableDocument()` returns a bounded `dmf-canvas-portable` document (version 1, or version 2 when it contains a Highlighter stroke; see [compatibility](COMPATIBILITY.md#highlighter-schema-3)) with stable node IDs and optional provenance. `loadPortableDocument(unknown)` validates before loading and currently requires a host with no authored originals; otherwise it returns `unsupported` without changing the board. Existing `saveDocument` / `loadDocument` schema-1/schema-2 behavior remains available. This is a local experiment, not a public stable API release.

`dmf-canvas/documents` exports `validatePortableDocument`, deterministic `migrateLegacyDocument`, and `importExcalidraw`. The importer accepts bounded version-2 scenes and returns `{adapter, adapterVersion, document, report}` without mutating a canvas. Adapter version 2 (0.3.0-alpha.3) converts Text, freehand, rectangles, ellipses, diamonds and unbound two-point lines and arrows; each Converted row lists what was approximated (ink, width, roughness, fill style, dash, opacity, arrowhead style, bound text). Documents that contain shapes are portable version 3. Bound arrows, multi-point lines and every other unsupported, deleted or malformed source element receive an Unsupported row with a reason. See the [document contract](architecture/CANVAS-DOCUMENT-SPEC.md) for limitations.
