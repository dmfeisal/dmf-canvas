# Astro installed-package example

Run `npm run test:astro` from the DMF Canvas repository root. The runner copies this recipe to a temporary project, copies the canonical host JS/CSS from `examples/shared/`, installs the locked Astro development dependency, packs Canvas and installs that archive with no source aliases or sibling paths. It builds the real static output and removes the fixture afterward.

To keep a runnable project:

```sh
node scripts/test-astro.mjs --keep
cd <printed-directory>
npm run dev
```

The printed project is self-contained and includes `INSTALL-PROVENANCE.json` with the exact packed archive integrity. This recipe deliberately has no registry dependency on the unpublished Canvas preview. Do not run the unprepared source directory directly: the host assets and installed archive are generated by the runner. Core has no Astro dependency.

`CanvasExample.astro` imports package CSS and registers a custom element. Each connected element mounts two independent instances once; disconnection disposes owners, Pencil, toolbar, subscriptions, observers, pending frames and file URLs. Pagehide/pageshow handle full-document lifecycle separately. No global canvas singleton or simulated lifecycle event is used. The layout enables Astro ClientRouter; `/away/` has no canvases. Returning makes fresh visit-local hosts rather than silently restoring drafts.

The host uses explicit owner registration, page-local clipboard and opt-in memory-only drafts. Save a board file before leaving if needed. It does not publish, upload, access portfolio data or persist edits automatically.

Browser checks: `CANVAS_TEST_SPACE_ID=<existing-agent-owned-id> npm run test:astro:browser`. The caller owns that space and its final cleanup. Build checks run in hosted CI; interactive browser checks use Ego Lite locally. Real touch devices, other browser engines and cross-origin iframe support remain unverified.
